#### ⚠️ OBSERVATION: Cache Eviction Logic

**Task Requirement:** "Cache TTL: calculated as `discharge_date + 30 days`; expired cache cleared by SW background sync"

**Finding:** The task specification mentions:
- OfflineCacheService should run cache eviction on app init
- Cache expiry based on discharge_date field value (not just config maxAge)
- Background sync should clear stale entries

**Current Implementation:** 
- ✅ `maxAge: 30d` configured at SW level (generic TTL)
- ❌ No `OfflineCacheService` implementation
- ❌ No application-layer cache eviction based on `discharge_date` + 30 days calculation
- ❌ No APP_INITIALIZER hook for cache cleanup

**Assessment:** The implementation uses Angular SW's built-in maxAge mechanism, which is correct. However, the task specification calls for application-layer eviction logic (`OfflineCacheService`) that goes beyond the SW config. This is a **minor scope gap** as the SW config alone meets Scenario 3 requirement ("cache TTL = 30 days").

**Recommendation:** If per-encounter discharge-date-based eviction is required, implement `OfflineCacheService` with APP_INITIALIZER. Current implementation is sufficient for user story acceptance.
